# 機能仕様

ゲームの各機能の**仕様(利用者から見える挙動と、保存データの扱い)**をまとめたものです。コードを変更するときは、
ここに書かれた挙動を変えないことが前提です(仕様を変えるときは、この文書とテストも合わせて更新します)。

- 教材データの追加は [CONTENT_GUIDE.md](CONTENT_GUIDE.md)
- 開発環境・コードの構成・変更時の注意は [DEVELOPMENT.md](DEVELOPMENT.md)

目次: 1. 構文トレーニング / 2. 保存データ / 3. キーボードショートカット / 4. BOTおまかせ復習 / 5. 表示テーマ / 6. 冠詞チェック / 7. HTMLの安全性

## 1. 構文トレーニング

単語ではなく「文」を学ぶモードです(ホーム →「🗣️ 構文トレーニング」)。単語のデータ・記録とは完全に分けてあります。

- **問題形式(=学習技能)**: 完成文の選択(意味 `meaning`)/ 空欄補充(`cloze`)/ 語順整序(`ordering`)。技能ごとに別々に記録し、習得は「その構文で出題される全技能」で判定します。
- **教材データの書き方**は [CONTENT_GUIDE.md](CONTENT_GUIDE.md) の「構文」を参照。
- **経験値**: 復習の時期が来た(または初めての)技能に正解すると +8。誤答直後の正解は +3、誤答は同じ技能で1回だけ +1。時期前の練習は 0。完走ボーナス +10 は、実際に経験値を得たセッションに1回だけ。構文からの経験値は1日120まで。単語の習得数・進化・称号には影響しません(構文には別の称号「ぶんけい〜」があります)。
- **復習**: 技能ごとに復習時期が来ます(間隔は単語と同じ 5分/1日/3日/7日)。復習セッションは、誤答のある構文 → 段階の低い構文 → 期限の古い構文の順に、期限の来た技能(正答率の低いもの優先)を出題します。**復習は選んでいる場面にかかわらず全場面の復習待ちが対象**で、構文メニューの「復習待ち」の件数と同じ範囲です(1回に最大6構文。残りは次の復習で)。復習待ちがなければ「全場面で復習待ちの構文はありません」と表示します。
- **単語との連携**: 新しい構文を選ぶときは、レベルの低い順(A1→A2)で、同じレベルなら「習得済みの単語を含む構文」を先にします。構文を始める前に、その構文で使う単語のうち単語学習でまだ習っていないものを一覧で確認できます(単語の記録は変更しません)。単語図鑑の詳細には「この単語を使う構文」が出ます。
- **構文図鑑**: 検索、場面・レベル・学習状況での絞り込み(30件ずつのページ送り)ができます。

## 2. 保存データ

学習記録は `localStorage` の `kotoba-monster-v1` に **形式 v4** で保存します(内容は下の「保存形式 v4」)。

### 保存形式 v4

`{ v:4, xp, best, w:{単語}, ph:{構文ID:{intro,n,ok,ng,st,last,at,due,sk:{meaning,cloze,ordering}}}, pbest, pd:{d,xp} }`

- 教材にない構文IDの記録も保持します(教材を一時的に外しても履歴が消えません)。不正な値は安全な初期値に直します。`src/lib/phraselib.js` が無い環境でも構文の記録は消しません。

### 保存キー一覧

| キー(`localStorage`) | 内容 |
|---|---|
| `kotoba-monster-v1` | 学習記録(形式 v4)。キー名の `v1` は、形式の版(`v:4`)とは別 |
| `kotoba-monster-v1-backup-v<旧版>` | 旧形式(v1〜v3)の記録を変換する前の元データ |
| `kotoba-monster-v1-corrupt` | 壊れていて読めなかった記録の退避 |
| `kotoba-monster-v1-before-import` | 記録を読み込む直前の記録の退避 |
| `kotoba-monster-v1-before-reset` | 「記録を消してはじめから」の直前の記録の退避 |
| `kotoba-monster-theme` | 表示テーマ(記録とは独立) |
| `kotoba-monster-keymap` | キーボードの割り当て(記録とは独立) |

### 保存と移行の挙動

- **旧形式の移行**: 読み込み時に、v4 より古い記録(v1〜v3。`v` がなければ v1 とみなす)を v4 に自動変換します(単語の履歴はそのまま、構文の記録は空で始まります)。変換前の元データは `kotoba-monster-v1-backup-v<旧バージョン>`(例: `…-backup-v1`、`…-backup-v3`)に書き残します。v4 で保存し直したあとも残るので、そこから復元できます。
- **壊れたデータ**: JSON として読めない・形式が違う場合は `…-corrupt` に退避し、新しい記録で起動します。
- **書き出し・読み込み**: ホームの「記録を書き出す/読み込む」で JSON(`format: 4`、構文の記録を含む)のバックアップ・復元ができます。読み込み前の記録は `…-before-import` に退避します。構文の記録(`ph`)を持たない古い書き出しを読み込んだときは、いまの構文の記録を残します。
- **リセット**: 「記録を消してはじめから」は、単語・構文の記録をすべて消します(消す前の記録は `…-before-reset` に退避)。
- **表示テーマ**: 記録とは別のキー `kotoba-monster-theme` に保存します(「表示テーマ」を参照)。記録の保存・移行・書き出し・リセットの対象には含まれず、互いに影響しません。

## 3. キーボードショートカット(カスタマイズ可能)

初期設定: **1〜4** = 選択肢を選ぶ(単語バトル・構文の選択式。語順整序では左から n 番目の語句を追加)/ **N** = 回答後に次へ(学習画面ではつぎの単語、BOTでは答えが出てから次の問題)/ **R** = 発音を再生(BOTは一時停止中だけ)/ **P** = BOTの一時停止・再開 / **Esc** = 戻る(出題・BOT再生の途中は確認を表示してから中断。答えは回答ごとに保存済み)。**矢印キー(↑↓←→)** は、選択肢(語順整序では語句カード)の間で選択中の項目を動かします(端でつながる)。決定は **Enter / Space**(数字キーと同じ回答処理)。矢印は固定のキーで割り当ては変えられず、動かす選択肢がない画面(回答後・ホームなど)では何もしません(スクロールを妨げません)。語順整序は、数字キーに頼らず **Tab または矢印で語句に移動 → Enter / Space で追加・取り消し・こたえ合わせ** ができます(語句・ボタンは普通の `<button>` です)。

- **キー設定**: ホームの「⌨️ キー設定」。「変更」を押してからキーを押すと再割り当て、「初期設定にもどす」で戻せます。使えるキーは英字・数字・Esc。**同じキーを2つの操作に割り当てることはできず**、理由を表示して確定しません。Tab・Enter・Space・F キー・矢印・記号・Ctrl/Command/Alt/Shift との組み合わせは割り当てできません(ブラウザの標準の操作と重なるため)。
- **保存**: `kotoba-monster-keymap`(`{ v: 1, keys: {...} }`)。学習記録(`kotoba-monster-v1`・形式 v4)・テーマ・バックアップ・書き出し・読み込みとは完全に別で、設定を変えても学習記録には一切触れません。壊れた値・重複のある値は初期設定として扱い、書き換えません。
- **発動しない場面**: 入力欄・セレクトボックス・テキストエリア・contenteditable の操作中、IME 変換中、Ctrl/Command/Alt/Shift を押しているとき、キーの押しっぱなし(repeat)。ブラウザの操作(Ctrl+R など)は妨げません。
- **仕組み**: キーは「いま画面にあって押せるボタン」の `click()` を呼びます。回答・次へ・語順カード・BOTの操作は、マウス・タップと同じ既存の処理(`handleAct`)を通ります。未回答のときは「つぎへ」のボタン自体がないので、勝手に進みません。
- **フォーカス**: 全画面を描き直したあと、同じボタン(なければ対のボタン=取り消し⇄追加・一時停止⇄再開、次に操作するボタン)へフォーカスを戻します(`kbAfterRender`)。
- **画面での案内**: 選択肢などのボタンにキーを小さく表示(`data-key`)し、`aria-keyshortcuts` を付けます。画面下に使えるキーの案内を出します(タッチ端末では非表示)。
- **確認(`tests/keyboard.test.js`)**: 初期設定の動作・設定の保存と再読み込み・重複と禁止キーの拒否・入力中/IME/修飾キー/押しっぱなしで発動しないこと・未回答で進まないこと・単語/構文/語順整序/BOTの操作・フォーカス・学習記録が変わらないこと。

## 4. BOTおまかせ復習(観戦・高速復習)

ホームの「🤖 BOTおまかせ復習」から使います。BOTが問題を出し、一定時間のあとに**正解と解説**を見せて、次の問題へ**自動で**進みます(動画のような自動再生)。何も操作しなくても、多数の単語・構文を短時間で見直せます。

- **設定**(開始前): 教材(単語/構文)・復習する対象(すべて/未学習/学習中/復習待ち/習得済み。件数つき)・再生する数(10問/30問/すべて)・順番(じゅんばん/ランダム)・再生速度(×0.5/×1/×1.5/×2)・フランス語の音声(ON/OFF)。
- **再生中**: 画面下の大きなボタンで「⏸ 一時停止/▶ 再開」「⏭ 次の問題」「⏹ 終了」。速度と音声は「⚙ 速度と音声」から変えられます(速度は次の表示から反映)。一時停止から再開すると、いまの場面(問題または答え)を最初から数え直して再生します。
- **表示する内容**: 単語は、正解の単語・日本語訳・発音の目安・例文・メモなど**教材データにあるもの**。構文は、正解の完成文・日本語訳・型・文法解説・語句の意味。空欄補充は空欄の答え、語順整序は正しい並びを示します。**教材にない解説は作りません**。
- **音声**: ONのとき、答えの表示でフランス語を読み上げ(音声問題は問題の提示でも)、**読み上げが終わるまで次へ進みません**(終了通知が来ない端末のため、上限15秒で進みます)。一時停止・次へ・終了・音声OFFでは読み上げを止めます。
- **学習記録は変わりません(観戦専用)**: BOTの答えは、経験値・育成状態・習熟度・正答率・連続正解・次回復習時刻・バトル/学習履歴・localStorage の記録のいずれにも反映されません。設定もメモリ上だけで保存しません(ページを開き直すと初期設定に戻ります)。
- **実装の方針**: 問題の生成・正解の判定・音声は既存の仕組みを再利用します(単語は `makeQ` と `allowedTypes`、構文は `PhraseLib.makeQuestion` と `checkChoice` / `checkCloze` / `orderingCheck`、音声は `speak`)。タイマーは「いまの表示の1本」と「読み上げの上限監視の1本」だけで、再生ごとの番号で古いタイマー・読み上げの通知を無効にします。BOTの画面を離れると(ホーム・他の画面・記録の読み込みなど、どの経路でも)タイマーと読み上げを必ず解除します。
- **教材を増やしても**: 対象は `WORDS` / `PHRASES` から自動で作られるので、追加した単語・構文はそのまま再生されます(コードの変更は不要)。

## 5. 表示テーマ(ライト / ダーク)

ホームの「表示テーマ」で、「🖥️ 自動」「☀️ ライト」「🌙 ダーク」を選べます。選んだテーマは、ほかの画面に移っても、ページを開き直しても維持されます。

- **保存**: `localStorage` の `kotoba-monster-theme`(値は `light` か `dark`。「自動」はキーなし)。**学習記録(`kotoba-monster-v1` と退避キー)とは独立**で、テーマの操作は学習記録を一切書き換えません。「記録を消してはじめから」「記録の読み込み」でもテーマは消えません(書き出しにも含まれません)。
- **優先順位**: 未選択(初回)は OS の設定(`prefers-color-scheme`)に従います(OS の設定を変えると追従)。ユーザーが選んだテーマは、OS の設定より優先されます。他のタブでの変更にも追従します。
- **不正な保存値**: 起動時に、テーマのキーだけを消して「自動」に戻します(記録のキーには触れません)。保存できない環境では、ページを開いている間だけメモリで選択を保ちます。
- **ちらつき防止**: `index.html` の先読みスクリプトが、CSS の読み込みより前に `<html data-theme>` を付けます。未選択のときは付けず、CSS の `@media (prefers-color-scheme: dark)` が最初の描画から効きます。`color-scheme` と `theme-color`(アドレスバーの色)も合わせます。
- **配色の管理**: `css/style.css` の先頭の3ブロック(ライト `:root` / ダーク `:root[data-theme="dark"]` / OS がダークのとき `@media`)が、色の変数(`--bg` `--surface` `--ink` `--mute` `--line` `--pri` `--ok` `--ng` …)を持ちます。**色はこの3ブロック以外に直接書かず、`var(--…)` で使います**(`filter: invert` のような全体反転も使いません)。新しい色を足すときは3ブロックすべてに同じ名前の変数を足し、ダークの2か所は同じ値にします。
- **確認(`tests/theme.test.js`)**: 切り替え・維持・OS との優先順位・不正値・保存できない環境・学習記録が変わらないこと・先読みスクリプト・色の直書きがないこと・変数の定義漏れがないこと・ライト・ダークの両方で文字色と背景色のコントラストが WCAG 2.2 の 1.4.3(通常サイズの文字 4.5:1)以上であること(色の定義から計算)・`opacity` による薄表示を使わないこと・修正対象外のライトの配色が変わっていないこと。
- **状態は色だけで示さない**: 正解・不正解は記号と文言(✅ 正解!/ おしい!)を併用し、回答後の選択肢にも CSS で ✓ / ✗ を付け、選択中のテーマボタンは「✓」と `aria-pressed` でも示します。
- **コントラストの設計(WCAG 2.2 の 1.4.3)**: 補助文字 `--mute` はライトで `#4f5a7e`(背景 `--bg` に対して 5.9:1。以前の `#6b7596` は 3.98:1)。回答後の正解・不正解は `opacity` で薄くせず、文字と背景の組み合わせ(ライトの `--ok` `#0f7a52` / `--ng` `#c93049` に白文字で 5:1 以上)で示します。無効なボタン・使用済みの語順カードも `opacity` ではなく専用色 `--dis-bg` / `--dis-ink`(4.5:1 以上)、入力欄の案内文字(placeholder)は `--mute` を使います。`opacity` は `#toast` のフェードだけです(`opacity` で文字と背景が合成されると、指定した色より実際のコントラストが下がるため)。
- **既知の課題**: 枠線 `--line`(ライト)は白い背景に対して非テキストのコントラスト(1.4.11: 3:1)には届いていません。今回(文字のコントラスト)の対象外で、デザイン変更を伴うため変更していません。

## 6. 冠詞チェックの仕様(`src/lib/wordlib.js` の `checkArticle`)

名詞の冠詞(`art`)と単語(`fr`)の組み合わせを、次の方針で確認します。

- `un / une / les / des` は省略しないので、どんな語でも問題なし(`un ami` は正しい)。
- 子音で始まる普通の語に `l'` を付けた場合だけ**エラー**(確実な誤り)。
- 母音・無音のhの語に `le/la`、有音のh・省略しない語に `l'` を付けた場合は**警告**(辞書にもとづく指摘のため、単語はゲームから除外されません)。
- `yaourt`(le / l' どちらも可)、`onze`・`oui`・`yacht`・`yoga` のように省略しない語は、誤警告を出しません。
- **辞書にない h / y 始まりの語は、正誤を断定しません**(エラーも警告も出ません)。辞書は `src/lib/wordlib.js` の `H_MUET` / `H_ASPIRE` / `NO_ELISION` / `ELISION_BOTH` にあり、確実に分かる語だけを追加してください。

## 7. HTMLの安全性

画面に表示する単語データ・検索語などの動的な文字列は、本文でも属性値(`data-id`・`value` など)でも、必ず `src/app.js` の `esc()` を通して埋め込みます。読み上げ(`speak`)には、エスケープ前の文字列を渡します(HTML用は `dispH()`、読み上げ用は `disp()`)。
